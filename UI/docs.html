Mesa Protocol Documentation

Mesa Protocol is an open-source, durable embedded finance orchestration framework built for Stellar and Soroban. It abstracts complex Web3 transaction pipelines into simple, composable primitives so developers can launch fintech applications in minutes.

lightbulb Simple Theory: Why Orchestration Matters

In traditional software, API calls either succeed or fail instantly. In blockchain financial applications, multi-step payments involve asynchronous network settlement, compliance holds, anchor webviews, and smart contract execution.

❌ Without Orchestration

If a server crashes at Step 3 of a 4-step cross-border transfer, funds are stuck mid-flight. Retrying raw transactions causes double-spends or sequence number errors.

✅ With Mesa Orchestration

Every step transition is checkpointed to database storage. If a server restarts, Mesa resumes right where it left off, automatically retrying Horizon calls safely.

account_tree 3-Tier System Architecture

PRODUCTION BLUEPRINT
1 LAYER 1 — Visual Studio & SDK Layer (@mesaprotocol/sdk)

Developers define financial workflows visually in Mesa Studio Canvas or programmatically using the fluent method-chaining TypeScript SDK.

↓ JSON AST Flow Definition ↓
2 LAYER 2 — Durable Runtime Engine (@mesaprotocol/runtime)

The core engine manages state persistence (Postgres/InMemoryPool), non-blocking step scheduling, webhook suspension keys, and Saga rollback compensations.

↓ Executable RPC Operations & Signatures ↓
3 LAYER 3 — Stellar Blockchain Infrastructure

Direct integration with Stellar Horizon RPC (on-chain payments), Soroban Smart Contracts (WASM RPC), SEP-10 (Web Auth), and SEP-24 (Anchors).

Built-in SEP-10 Web-Auth challenge signing & JWT caching, plus SEP-24 Anchor deposit/withdrawal webviews.

4. Durable Saga Rollbacks

State persistence via PostgreSQL/InMemoryPool with automatic compensating transactions if a step fails.

Ledger congestion or Horizon RPC timeouts trigger automatic exponential backoff retry loops with zero data loss.

3-Minute Quickstart Guide

Set up Mesa SDK in your Node.js or Next.js project and run your first workflow in 3 simple steps.

1

Install NPM Packages

bash
npm install @mesaprotocol/sdk @mesaprotocol/runtime @mesaprotocol/schema
2

Configure Environment Variables

.env
SENDER_SECRET=SD6K5ODP2TKUDFEX6E5FQUZMKCJZDJPM35OZAA3AP6VEMVRROEC5MRQP HORIZON_URL=https://horizon-testnet.stellar.org STELLAR_NETWORK=TESTNET PORT=3001
3

Create & Run Your First Workflow

mesa-server.ts 
import 'dotenv/config';
import { startServer } from '@mesaprotocol/runtime';

const port = Number(process.env.PORT || 3001);

startServer(port).then(() => {
  console.log(`🚀 Mesa Production Runtime Server running on http://localhost:${port}`);
  console.log(`📊 Dashboard Console: http://localhost:${port}/dashboard`);
});
Documentation chevron_right Providers Reference

9 Core Execution Providers

Mesa features 9 modular execution providers that handle everything from Stellar payments and SEP anchors to Soroban smart contracts and Saga rollbacks.

1. sep10 Stellar Auth

Executes SEP-10 Web-Auth challenge signing & retrieves cached JWT access tokens.

.sep10Auth({ domain: 'anchor.stellar.org' })
2. anchor SEP-24 Webview

Triggers interactive anchor deposit/withdrawal flows and returns webview interactive URLs.

.anchor({ action: 'deposit', asset: 'USDC' })
3. soroban Smart Contracts

Invokes Soroban WASM smart contract functions via RPC with typed parameter serialization.

.soroban({ contractId: 'C...', method: 'transfer' })
4. stellar Horizon Primitives

Submits native XLM & token payment operations with automatic Horizon fee management.

.payment({ asset: 'XLM', amount: 50, to: 'G...' })
5. approval Compliance Hold

Suspends execution state and waits for an operator/compliance manual approval sign-off.

.approval({ approverRole: 'compliance-officer' })
6. condition Dynamic Router

Evaluates dynamic expression conditions for directed branch routing.

.condition({ expression: 'amount >= 100' })
7. delay Screening Delay

Schedules retry-safe non-blocking delays (e.g. 5-second sanctions window).

.delay({ seconds: 5 })
8. webhook External Callback

Parks execution until an external HTTP webhook callback resumes the flow.

POST /webhooks/resume {"suspensionKey": "..."}
9. compensation Saga Rollback

Executes distributed Saga compensating transactions if downstream steps fail, ensuring user refunds.

.compensate({ reason: 'Refund deposit on payment failure' })
Documentation chevron_right SDK API Reference

Fluent FlowBuilder SDK API

The Mesa TypeScript SDK uses a type-safe method chaining builder pattern to assemble financial workflows. 

import { Mesa } from '@mesaprotocol/sdk';

export const flow = Mesa.flow('Cross-Border Remittance Corridor', 'cross-border-remittance-corridor')
  // 1. SEP-10 Authentication Challenge
  .sep10Auth({
    domain: 'anchor.stellar.org',
    accountSecretRef: 'SENDER_SECRET'
  })
  // 2. Sanctions Screening Window (2 seconds)
  .delay({ seconds: 2 })
  // 3. Compliance Manual Approval Gate
  .approval({ approverRole: 'compliance-officer' })
  // 4. Stellar XLM Payment
  .payment({
    asset: 'XLM',
    amount: 50,
    to: 'GA7IL52JSHMHWCP6HEPYE6IXIR5IZGDEISUFSJVPKCAU7NE7A6EJOFMN',
    senderSecretRef: 'SENDER_SECRET',
    horizonUrl: 'https://horizon-testnet.stellar.org'
  })
  .build();

Stellar SDK vs. Mesa Protocol

See how Mesa eliminates over 150 lines of repetitive Stellar SDK boilerplate while adding state persistence and retries.

cancel Without Mesa (Raw Stellar SDK) 
import * as StellarSdk from '@stellar/stellar-sdk';

const server = new StellarSdk.Horizon.Server(
  'https://horizon-testnet.stellar.org'
);
const keypair = StellarSdk.Keypair.fromSecret(
  process.env.SENDER_SECRET
);
const account = await server.loadAccount(
  keypair.publicKey()
);
const fee = await server.fetchBaseFee();

const tx = new StellarSdk.TransactionBuilder(
  account, { fee: fee.toString(), networkPassphrase: ... }
)
  .addOperation(StellarSdk.Operation.payment({
    destination: 'GA7IL...',
    asset: StellarSdk.Asset.native(),
    amount: '50'
  }))
  .setTimeout(30)
  .build();

tx.sign(keypair);
await server.submitTransaction(tx);
// + 120 lines for SEP-10, retries & DB state...
check_circle With Mesa Protocol 
import { Mesa } from '@mesaprotocol/sdk';

export const flow = Mesa.flow('remittance')
  .sep10Auth({ domain: 'anchor.stellar.org' })
  .delay({ seconds: 2 })
  .approval({ approverRole: 'compliance' })
  .payment({
    asset: 'XLM',
    amount: 50,
    to: 'GA7IL...'
  })
  .build();

// ✅ 4 lines replace 150+ lines!
// ✅ Includes durable state & retries!
